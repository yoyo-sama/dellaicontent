# ComfyUI Workflows — AI Content Studio (GB10)

Deux familles de fichiers :
- **Racine** : workflows complets au format UI, à glisser-déposer dans ComfyUI (http://localhost:8188). **Legacy** (Flux2/Ernie/Z-Image/LTX 2.3, plus utilisés par l'app), voir tableau plus bas.
- **`api/` + `manifest.json`** : templates mono-branche au format API avec placeholders (`{{PROMPT}}`, `{{SEED}}`, `{{WIDTH}}`, `{{HEIGHT}}`, `{{BATCH}}`, `{{DURATION}}`, `{{FRAMES}}`, `{{IMAGE}}`, `{{IMAGE2}}`), consommés par l'UI du studio (http://localhost:8090) qui alimente ses menus Pipeline/Modèle depuis le manifest. Sorties préfixées `studio/`. Fichiers actuels : `krea2_t2i.json`, `qwen_edit_i2i.json`, `qwen_edit_dual.json`, `ltx25_{t2v,i2v,flf2v}.json`, `minimax_h3_{t2v,i2v,r2v}.json`.

Fonctions construites dynamiquement par l'UI (pas de template statique) :
- **Animatic multi-images FLF2V** : pipeline `sequence2video` du menu (entrée `flf2v_chain` du manifest, `file: null`, construit par `buildFLF2VGraph` en JS, LTX 2.5) — 2 à 6 images (upload ou galerie), durée par segment (1–8 s, frames 8n+1), ratio appliqué, soumis via le bouton Generate → `studio/sequence`. Le formulaire s'adapte : la section séquence n'apparaît que pour ce pipeline ; variantes/durée globale/image d'entrée/marchés masqués selon le pipeline.
- **Marchés cibles Localized Assets** (pipeline image2image) : un job par marché sélectionné (North America, Latin America, Europe, Middle East, Africa, Asia) avec adaptation culturelle du prompt, seeds décalés.
- **Storyboard + Animatic v2** (pipeline `storyboard_v2`, scénario Storyboard) : une **séquence de jobs ComfyUI indépendants** orchestrée en JS (pas un graphe unique) — (1)+(2) fiches personnage ET décor figées par gemma4:e4b puis rendues en image (Krea 2 Turbo, fond neutre) = les **ancres** ; (3) gemma4:e4b découpe le brief en N plans `{camera, lighting, action, emotion}` (4 à 16, repli presets sans LLM) ; (4) **N keyframes ancrées dual** : 1 job Qwen-Image-Edit 2509 Lightning par plan, qui remet en scène le personnage ET le décor des deux ancres (identité figée, prompt entièrement positif car cfg 1) — le modèle d'ancrage est désigné par le champ manifest `anchor`, une bascule de modèle = une ligne ; (5) grille contact-sheet adaptative (`ImageStitch`, carrée `⌈√n⌉` colonnes) ; (6) **1 cut vidéo LTX 2.5 i2v par keyframe** (2 passes, template `api/ltx25_i2v.json` tel quel, prompt ancré sur scène+personnage+décor+mouvement, pas le mouvement seul) + tenue optionnelle du plan final ; (7) assemblage en **cuts francs** (`LoadVideo`→`GetVideoComponents`→`ImageBatch`+`AudioConcat`→`CreateVideo`) → `studio/story/animatic`. Deux modes UI : **Auto** (chaîne complète en un clic) et **Réalisateur** (3 arrêts : plans éditables → keyframes régénérables/verrouillables → animatic). Détail complet : `docs/ARCHITECTURE.md`.
- **Personnage + décor cohérents** (pipeline `reference2video`, scénario Storyboard) : mêmes ancres charsheet/locsheet Krea 2 que `storyboard_v2`, mais passées directement comme `ref_image_0`/`ref_image_1` d'un seul job `MiniMaxH3ReferenceToVideo` (template `api/minimax_h3_r2v.json`) — pas de découpage en plans ni d'animatic, une seule vidéo. Turbo Minimax H3 activable (booléen seulement, pas de choix de steps) et résolution pilotable par mégapixels. Jusqu'à 7 images, 3 vidéos et 3 audios de référence supplémentaires peuvent désormais être attachés en plus des 2 planches auto-générées (`addMinimaxRefs`). Détail : `docs/ARCHITECTURE.md`.
- **Campagne complète** (pipeline `campaign_full`, scénario Campaign) : une seule tâche = posters 2:3 + thumbnails 16:9 (× variantes) + social 1:1 (Krea 2 Turbo) + teaser vertical LTX 2.5 (2 passes + upscale, audio natif) → `studio/campaign/`.

Tout est core-nodes-only (aucun custom node).

Notes :
- Les prompts par défaut reprennent les exemples de la spec (`ai_content_studio_media_entertainment_gb10.md`) ; à adapter dans les nœuds `CLIPTextEncode`.
- `localized_assets.json` : charger l'asset maître dans le nœud `LoadImage`.
- Les sorties sont préfixées `campaign/`, `storyboard/`, `localized/` dans le dossier output de ComfyUI.
- Audio LTX 2.5 / Minimax H3 : généré conjointement à la vidéo depuis le prompt, via un **VAE audio dédié** distinct du VAE vidéo (`ltx-2.5-audio-vae-bf16.safetensors` / `minimax_h3_audio_vae_fp32.safetensors`) — contrairement à LTX 2.3 (legacy) où l'audio VAE était inclus dans le checkpoint. Dans l'app : case "Générer l'audio" pour les pipelines vidéo.
- Le pipeline Animatic (FLF2V) de l'app n'est proposé que dans le scénario Storyboard + Animatic, tout comme `storyboard_v2` et `reference2video`.
- Ordres de grandeur mesurés en rendu réel sur ce GB10 pour `storyboard_v2` **ancrage double** (run LOT 4, N=4, brief astronaute, 2026-07-17 22:47→23:03, charsheet/locsheet encore en Ernie-Image à cette date — remplacé depuis par Krea 2, timings à revérifier) : 3 appels gemma (fiche personnage ≈10.5 s, fiche décor ≈10.3 s, N plans ≈28.5 s), 4 keyframes Qwen-Edit **dual** 27–32 s chacune (114.4 s cumulé), grille <1 s, 4 cuts LTX i2v 2 s 107–158 s chacun + 1 cut de tenue 115 s (619.9 s cumulé) — **total ComfyUI seul (charsheet→animatic, `/history`) ≈ 16 min 16 s**. Détail et run N=8 pré-ancrage-double : `docs/ARCHITECTURE.md` / rapport de qualification LOT 3.
- Minimax H3 : longueur calée sur la grille **17n+5** (pas 8n+1 comme LTX), dimensions arrondies au multiple de 32 inférieur — voir LESSONS piège n°11. Turbo (LoRA `minimax_h3_turbo_v4_step600_ema_pruned_comfyui.safetensors`) validé **ON à 8 steps** (qualité ≈ 20 steps sans LoRA, 2,5× plus rapide). Pour t2v/i2v, 4/6/8 steps sont désormais tous valides : 6 et 8 gardent ce LoRA, 4 bascule automatiquement sur un second LoRA dédié 4-steps (`minimax_h3_fl2v_turbo_4step_v1.2_768p_comfyui_bf16.safetensors`, addendum LESSONS piège n°12) — ne jamais faire tourner le LoRA d'origine à 4 steps directement, ce cas précis reste cassé. r2v (checkpoint différent, non compatible avec ce second LoRA) reste 8 steps ou OFF uniquement, pas de choix de steps.
- Krea 2 : négatif routé par `ConditioningZeroOut` sur le positif — le texte négatif n'est **jamais encodé**, contrairement à un cfg>1 classique (LESSONS piège n°16). Toute contrainte doit être formulée positivement dans le prompt.
- LoRA de style (Krea 2 image / Minimax H3 vidéo, en plus des LoRA turbo ci-dessus) : sélecteur disponible aussi bien dans l'app formulaire (`index.html`) que dans Canvas (`canvas.html`) — liste découverte en direct depuis `loras/Krea2/`/`loras/H3/` sur disque (`/object_info/LoraLoaderModelOnly`), plus de liste curée à la main ; ajout de nouveaux fichiers possible directement depuis le panneau Model Management de l'app (upload navigateur uniquement).
- Modèles legacy testés en rendu réel le 2026-07-06 (workflows racine, vidéos LTX 2.3 testées en durée réduite ~2 s) ; Krea 2/LTX 2.5/Minimax H3 qualifiés lors du LOT 1 (2026-09-01, détail `docs/NOUVEAUX-MODELES-LOT1.md`).
